# Task45:U03-QA-1 — US-03 submission test cases TC-03-01 to TC-03-08

Derived from the acceptance criteria and test table in [US-03](../stories/sprint1/US-03.md). The automated tests run in CI against PostgreSQL (`backend/src/test/java/com/tu/clubhub/application/`). The UI column is filled in when QA runs the case in the browser.

**UI prerequisites:** demo data loaded with `scripts/seed-dev-data.sh`, the routed application form from Task53, and two mock accounts (password `tu-clubhub-demo`): `student-demo` runs ชมรมเขียนโปรแกรม, and `applicant-demo` applies to it. The UI runs are blocked until the Task53 form is merged.

| TC | AC | Case | Expected | Automated tests | UI result (Pass/Fail, date, tester) |
|---|---|---|---|---|---|
| TC-03-01 | AC-01, AC-06 | Eligible student opens an open round, fills the motivation, answers and one HTTPS link, submits | 201 with status `SUBMITTED`; one application, its answers, links and one initial history row are saved | `commitsSubmittedReceiptAnswersLinksAndExactlyOneInitialHistory`, `applicationFormListsTextQuestionsInOrderWithoutCsrfOrWrites` | |
| TC-03-02 | AC-01 | Not logged in; graduated or non-student account; a request carrying another `applicantId` | 401; 403; rejected, and no application for anyone | `httpBoundaryUsesSessionsCsrfAndRejectsClientIdentity`, `rejectsInactiveOrMissingStudentProfileEvenForAdmin` | |
| TC-03-03 | AC-01 | Round that is a draft, does not exist, or belongs to an inactive club | 404 for each, with no detail about which | `hidesMissingRoundInactiveClubAndNeverPublishedRound`, `applicationFormChecksSessionIdStudentAndVisibilityInOrder` | |
| TC-03-04 | AC-02 | Empty motivation, missing or blank required answer, answer to another round's question; optional answer left out | 400 naming each field, nothing saved; leaving the optional answer out still submits | `rejectsRequiredMissingBlankForeignDuplicateAndOverlongAnswersWithoutPartialWrites`, `countsAnswerLengthBeforeTrimmingAndAllowsOptionalOmission` | |
| TC-03-05 | AC-03 | Link `https://…`; then `http://`, no scheme, `javascript:`, spaces, userinfo, over 2,048 characters | HTTPS accepted; the others 400 `INVALID_HTTPS_URL` on that link | `rejectsInvalidOptionalUrlsWhenLinkIsPresent`, `invalidHttpsUrlHttpErrorMatchesOpenApiExample` (no automated case for the 2,048 limit; check it in the UI run) | |
| TC-03-06 | AC-04 | Submit before `opens_at`, exactly at `closes_at`, and after it | 409 `ROUND_NOT_OPEN`, `ROUND_CLOSED`, `ROUND_CLOSED`; opening is inclusive | `openingIsInclusiveAndClosingIsExclusive`, `rejectsNotYetOpenManuallyClosedAndPreviouslyPublishedCancelledRounds`, `applicationFormReportsUnavailableRoundsWithSubmissionReasons` | |
| TC-03-07 | AC-04 | Round closes while the form is open: `applicant-demo` opens the form, `student-demo` closes the round (`PATCH /api/v1/clubs/{clubId}/rounds/{roundId}` with `{"action":"CLOSE","version":…}`), then the applicant submits | 409 `ROUND_CLOSED` shown on the form, no application saved; a submit racing the close either commits fully or is rejected | `rechecksDeadlineOrManualCloseAfterWaitingForActualRoundLock`, `waitingHttpRequestRechecksClosingTimeAfterRoundLock` | |
| TC-03-08 | AC-05 | Submit twice to one round, double-click, concurrent requests; then apply to a club already joined, and with five ACTIVE memberships | One application only, others 409 `APPLICATION_ALREADY_EXISTS`; 409 `ALREADY_MEMBER`; 409 `MEMBERSHIP_LIMIT_REACHED` | `sameStudentConcurrentHttpSubmissionsCommitExactlyOnce`, `rejectsDuplicateIncludingWithdrawnApplicationsAndPreservesOriginalHistory`, `rejectsFiveEffectiveMembershipsAcrossAllClubTypes` | |

AC-06 also asks that the new application appear in the applicant's history at once. That page is US-04 (`GET /api/v1/me/applications`, not implemented), so it is not covered here.
