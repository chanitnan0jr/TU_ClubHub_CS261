# US-03: กรอกและส่งใบสมัครเข้าชมรม

## Description

**As a:** นักศึกษาที่เข้าสู่ระบบด้วยบัญชีนักศึกษา มธ.  
**I want to:** เลือกรอบรับสมัคร กรอกเหตุผล คำตอบคัดเลือก เพิ่มลิงก์เอกสาร และยืนยันการส่งใบสมัคร  
**So that:** ฉันสามารถส่งข้อมูลประกอบการสมัครได้ครบถ้วน และมีประวัติยืนยันการส่งสำหรับติดตามผล

**Sprint:** Sprint 1  
**Priority:** High | **Estimate:** 8 Story Points

**Pre-conditions:** Login ด้วยบัญชี มธ. สำเร็จ, รอบอยู่ในช่วงเปิดรับ, ไม่เคยส่งใบสมัครซ้ำในรอบเดิม  
**Post-conditions:** บันทึกใบสมัคร คำตอบ ลิงก์ สถานะเริ่มต้นเป็น Pending และแสดงในประวัติการสมัคร

## Acceptance Criteria

- **AC-01:** นักศึกษาที่ผ่านการยืนยันตัวตนด้วยบัญชี มธ. สามารถเลือกรอบรับสมัครที่กำลังเปิดอยู่ กรอกเหตุผล และตอบคำถามคัดเลือกได้
- **AC-02:** ระบบต้องตรวจสอบความครบถ้วนของข้อมูลบังคับ หากกรอกไม่ครบต้องแจ้งเตือนช่องที่ต้องแก้ไขและยังไม่ส่งใบสมัคร
- **AC-03:** ระบบต้องตรวจสอบรูปแบบลิงก์เอกสาร (Portfolio/Resume) ให้เป็น HTTPS URL ที่ถูกต้องเท่านั้น
- **AC-04:** Backend ต้องตรวจสอบช่วงเวลาและปฏิเสธการส่งใบสมัครที่ส่งนอกช่วงเปิดรับ หรือหลังปิดรับสมัครแล้ว
- **AC-05:** ระบบต้องตรวจสอบและป้องกันการส่งใบสมัครซ้ำในรอบเดิมของชมรมเดียวกัน โดยอนุญาตให้ส่งได้เพียง 1 รายการต่อรอบ
- **AC-06:** เมื่อบันทึกสำเร็จ ข้อมูลใบสมัคร คำตอบ และลิงก์ต้องถูกจัดเก็บครบถ้วน สถานะเริ่มต้นเป็น “รอพิจารณา (Pending)” และแสดงในหน้าประวัติทันที

**นโยบายเพิ่มเติมตามโจทย์:** ตรวจเพดานสมาชิกภาพไม่เกิน 5 ชมรม (อ้างอิงข้อบังคับ มธ. ว่าด้วยกิจกรรมนักศึกษา พ.ศ. 2563 ข้อ 65) ตอนส่งใบสมัครด้วย แม้ AC ทั้ง 6 ข้อจะไม่ได้กล่าวถึง จึงไม่ถือเป็นเกณฑ์ตรวจรับจนกว่าทีมจะยืนยัน

## ข้อมูลหลัก

| กลุ่มข้อมูล | สิ่งที่บันทึก |
|---|---|
| ใบสมัคร | ผู้สมัคร (จาก Session) รอบรับสมัคร ชมรมของรอบ เหตุผลในการสมัคร เวลาที่ส่ง และสถานะเริ่มต้น |
| คำตอบ | คำตอบแบบข้อความ 1 รายการต่อคำถามของรอบที่ส่ง |
| ลิงก์เอกสาร | ชื่อหรือคำอธิบายลิงก์ และ URL แบบ HTTPS |
| ประวัติสถานะ | รายการแรกของใบสมัคร (ยังไม่มีสถานะก่อนหน้า → รอพิจารณา) พร้อมเวลาและผู้ดำเนินการ |

ตารางนี้แสดงข้อมูลหลักของ Story ไม่ใช่ Schema ทั้งหมด ชื่อ Field ให้ยึด ERD ล่าสุด

**สถานะเริ่มต้น:** ใน ERD เก็บเป็น `SUBMITTED` และแสดงต่อผู้ใช้เป็น “รอพิจารณา (Pending)” ในเอกสารนี้ Pending หมายถึงสถานะเดียวกัน ไม่เพิ่มสถานะใหม่

## Business Rules

| รหัส | กฎ | อ้างอิง |
|---|---|---|
| BR-01 | ผู้สมัครคือผู้ใช้ใน Session เท่านั้น ห้ามรับรหัสผู้สมัครจาก Request ยังไม่ Login ให้ปฏิเสธ (401) และต้องเป็นนักศึกษาที่มีสิทธิ์สมัคร ผลยืนยันบัญชีสำเร็จอย่างเดียวไม่พอ ต้องตรวจประเภทผู้ใช้และสถานะนักศึกษาตามตารางที่ตกลง หากข้อมูลไม่ครบหรือสถานะที่ไม่รู้จักให้ปฏิเสธ (403) | AC-01 |
| BR-02 | รอบต้องมีอยู่และเผยแพร่แล้ว หากไม่มีหรือเป็น Draft ให้ตอบ 404 เหมือนกัน ไม่เปิดเผยว่ามี Draft | AC-01 |
| BR-03 | ช่วงเวลารับสมัครคือ รอบเผยแพร่แล้ว และ `opens_at <= เวลา Server < closes_at` และ `closed_at` เป็น `null` ตามกฎ US-07 ตรวจที่ Backend ตอนบันทึกจริง ไม่ใช่ตอนเปิดฟอร์มหรือจาก Frontend เวลาเท่ากับ `closes_at` ปฏิเสธ และต้องตรวจซ้ำใน Transaction เดียวกับการบันทึก เพื่อไม่ให้รับใบสมัครที่ชนกับการสั่งปิดรอบ | AC-04 |
| BR-04 | ผู้สมัครส่งได้ 1 ใบสมัครต่อรอบ เนื่องจากรอบสังกัดชมรมเดียว จึงเท่ากับ 1 ใบสมัครต่อชมรมต่อรอบ ตรวจใน Service และใช้ Unique Constraint `(round_id, applicant_id)` เป็นด่านสุดท้าย หากส่งพร้อมกันหลายคำขอ ต้องสำเร็จเพียง 1 รายการและที่เหลือได้ 409 โดยไม่มีข้อมูลซ้ำ การสมัครต่างรอบของชมรมเดียวกันไม่ขัดกฎนี้ | AC-05 |
| BR-05 | ข้อมูลบังคับ ได้แก่ เหตุผลในการสมัครและคำตอบของคำถาม Required ต้องไม่ว่างหรือมีแต่ช่องว่าง (ตาม US-08 BR-03) ส่วนคำถามไม่บังคับเว้นได้ คำตอบต้องอ้างคำถามของรอบที่สมัครเท่านั้น และไม่รับคำตอบซ้ำของคำถามเดียวกัน ตอบกลับเป็นรายการช่องที่ต้องแก้ไข และไม่สร้างข้อมูลใด ๆ ถ้ามีข้อผิดพลาด | AC-01, AC-02 |
| BR-06 | ลิงก์เอกสารต้องผ่านเงื่อนไขตารางด้านล่างทุกข้อ หากผิดข้อใดข้อหนึ่งให้ปฏิเสธลิงก์นั้น และ Backend เก็บเฉพาะ URL ไม่เปิดหรือดาวน์โหลดลิงก์ปลายทาง | AC-03 |
| BR-07 | เพดานสมาชิกภาพ: นับ `ClubMembership` สถานะ ACTIVE แยกตามชมรม หากครบ 5 ชมรมให้ปฏิเสธใบสมัครใหม่ นับเฉพาะสมาชิกภาพที่มีผล ไม่นับใบสมัครที่รอพิจารณา ผ่านรอยืนยัน ไม่ผ่าน สละสิทธิ์ หมดเวลา และสมาชิกภาพที่สิ้นสุดแล้ว หากเป็นสมาชิก ACTIVE ของชมรมนั้นอยู่แล้วให้ปฏิเสธด้วย | นโยบายตามโจทย์ |
| BR-08 | การตรวจเพดานตอนส่งใบสมัครมีไว้แจ้งผู้ใช้ให้เร็ว ไม่ใช่การรับประกันว่ายืนยันสิทธิ์ได้ เพราะผู้สมัครอาจยื่นหลายชมรมแล้วยืนยันจนเต็มเพดานภายหลัง US-05 ต้องตรวจเพดานซ้ำใน Transaction ตอนยืนยันสิทธิ์ | นโยบายตามโจทย์ |
| BR-09 | บันทึกใบสมัคร คำตอบ ลิงก์ และประวัติสถานะรายการแรกใน Transaction เดียว หากขั้นตอนใดล้มเหลวให้ Rollback ทั้งหมด และตอบสำเร็จหลัง Commit เท่านั้น หากระบบสร้างการแจ้งเตือนยืนยันการส่ง ให้อยู่ใน Transaction เดียวกัน | AC-06 |
| BR-10 | สถานะเริ่มต้น `SUBMITTED` แสดงเป็น “รอพิจารณา (Pending)” ผู้สมัครเห็นในประวัติ (US-04) ทันทีหลังบันทึกสำเร็จ โดยไม่เห็นผลพิจารณาหรือหมายเหตุกรรมการ | AC-06 |
| BR-11 | Frontend ตรวจข้อมูลเพื่อความสะดวกเท่านั้น Backend ตรวจทุกข้อเสมอ และตอบเหตุผลที่แยกกันได้ ได้แก่ ยังไม่เปิดรับ ปิดรับแล้ว สมัครซ้ำ ถึงเพดานสมาชิก เป็นสมาชิกอยู่แล้ว และข้อมูลไม่ถูกต้อง | AC-02, AC-04, AC-05 |

### เงื่อนไขลิงก์เอกสาร (BR-06)

| เงื่อนไข | ผล |
|---|---|
| Scheme เป็น `https` (ไม่สนตัวพิมพ์เล็ก/ใหญ่) และมี Host | ผ่าน |
| `http`, `ftp`, `javascript:`, `data:`, `file:` หรือไม่มี Scheme | ปฏิเสธ |
| มีช่องว่างหรืออักขระควบคุมใน URL | ปฏิเสธ |
| มี Username/Password ใน URL เช่น `https://user:pass@host` | ปฏิเสธ |
| ยาวเกินที่ ERD กำหนดสำหรับ URL | ปฏิเสธ |
| ปล่อยว่าง | ผ่านได้ เว้นแต่ทีมตกลงให้บังคับแนบ |

การผ่านเงื่อนไขนี้ตรวจเพียงรูปแบบ URL ไม่ได้รับประกันว่าเปิดเอกสารได้จริงหรือตั้งสิทธิ์ให้กรรมการเข้าถึงแล้ว

### ลำดับตรวจสอบและผลปฏิเสธ (ข้อเสนอ)

| ลำดับ | เงื่อนไขที่ไม่ผ่าน | ผลตอบกลับ |
|---|---|---|
| 1 | ยังไม่ Login | 401 |
| 2 | ไม่ใช่นักศึกษาที่มีสิทธิ์สมัคร | 403 |
| 3 | ไม่พบรอบ หรือรอบยังไม่เผยแพร่ | 404 |
| 4 | ยังไม่เปิดรับ / ปิดรับแล้ว | 409 พร้อมรหัสเหตุผลที่ต่างกัน |
| 5 | ข้อมูลหรือลิงก์ไม่ถูกต้อง | 400 พร้อมรายการช่องที่ต้องแก้ |
| 6 | สมัครซ้ำในรอบเดิม | 409 |
| 7 | เป็นสมาชิกชมรมนี้อยู่แล้ว / ถึงเพดาน 5 ชมรม | 409 พร้อมรหัสเหตุผลที่ต่างกัน |
| 8 | ผ่านทั้งหมด | 201 พร้อมรหัสใบสมัครและสถานะ Pending |

รหัสสถานะและชื่อรหัสเหตุผลเป็นข้อเสนอ ให้ยึดตาม API Specification ที่ทีมตกลง

## ขอบเขตและเรื่องที่ยังต้องตกลง

- **อยู่ใน Story:** เลือกรอบที่เปิดรับ กรอกเหตุผลและคำตอบ เพิ่มลิงก์ ตรวจสิทธิ์ ช่วงเวลา สมัครซ้ำ เพดานสมาชิกภาพ และบันทึกใบสมัครสถานะ Pending
- **ไม่รวม:** บันทึกฉบับร่าง การแก้ไขหรือถอนใบสมัครหลังส่ง การอัปโหลดไฟล์ การตรวจว่าลิงก์เปิดได้จริง และการประกาศผล
- **ความสัมพันธ์กับ Story อื่น:** US-02 ให้ปุ่มไปสมัคร, US-07 กำหนดกฎเวลาและการปิดรอบ, US-08 กำหนดคำถามและ Required, US-04 แสดงประวัติและสถานะ, US-05 ตรวจเพดานสมาชิกภาพซ้ำตอนยืนยัน
- **ยังต้องตกลง:**
  - ตาราง `statusid` ของ TU ว่าสถานะใดมีสิทธิ์สมัคร
  - เพดาน 5 ชมรมใช้กับชมรมประเภทใด (ข้อ 65 พูดถึงชุมนุมระดับมหาวิทยาลัย ส่วนชมรมระดับคณะหรือหอพักยังไม่ยืนยัน) และระบบนับได้เฉพาะสมาชิกที่บันทึกในระบบ
  - โควตาจำนวนใบสมัครพร้อมกัน (เช่น 3 ชมรม) ยังไม่ใช่กติกา และไม่รวมใน Story นี้
  - ลิงก์เป็นข้อมูลบังคับหรือไม่ จำนวนลิงก์สูงสุด และความยาวสูงสุดของเหตุผลกับคำตอบ
  - หากเพิ่มการถอนใบสมัคร Unique `(round_id, applicant_id)` จะกันการสมัครรอบเดิมซ้ำหลังถอน ต้องตัดสินนโยบายและปรับ ERD ให้ตรงกัน
  - Use Case Specification ฉบับแนบยังเขียนเป็นการอัปโหลดไฟล์ ต้องแก้เป็นลิงก์ให้ตรง Story นี้
