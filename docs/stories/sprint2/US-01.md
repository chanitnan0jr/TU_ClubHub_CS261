## 1. Description

**As a:** นักศึกษาที่ต้องการค้นหาชมรมที่ตรงกับความสนใจ  
**I want to:** ค้นหาชมรมด้วยชื่อ กรองตามหมวดหมู่หรือแท็กความสนใจ และดูรายการชมรมโดยไม่ต้อง Login  
**So that:** ฉันสามารถค้นพบชมรมที่สนใจได้สะดวก และเลือกเพื่อศึกษารายละเอียดเพิ่มเติม

## 2. Pre-conditions

- มีข้อมูลชมรม หมวดหมู่ และแท็กความสนใจในระบบ
- ผู้ใช้งานสามารถเข้าถึงหน้าค้นหาชมรมได้ โดยไม่ต้องมีบัญชีหรือ Session ที่ Login แล้ว
- ระบบมีเกณฑ์ระบุว่าชมรมใดอนุญาตให้แสดงข้อมูลสาธารณะ โดยใช้เกณฑ์เดียวกับ US-02

กรณีไม่มีชมรมที่เปิดเผยได้ยังต้องจัดการเป็นสถานะรายการว่างอย่างเหมาะสม ไม่ถือเป็นข้อผิดพลาดของหน้าจอ

## 3. Post-conditions

- แสดงรายการชมรมที่เปิดเผยได้และตรงตามเงื่อนไขค้นหา/ตัวกรองที่ใช้อยู่
- ผู้ใช้เห็นตัวกรองที่กำลังใช้งาน และสามารถเปลี่ยนหรือล้างตัวกรองได้
- ผู้ใช้เลือกชมรมเพื่อเปิดหน้ารายละเอียดตาม US-02 ได้
- การค้นหาไม่แก้ไขข้อมูลชมรม หมวดหมู่ หรือแท็กในระบบ

## 4. Acceptance Criteria

- **AC-01:** ผู้ใช้งานทั่วไปสามารถค้นหาชมรมด้วยชื่อ กรองตามหมวดหมู่ (วิชาการ, กีฬา, ศิลปวัฒนธรรม, บำเพ็ญประโยชน์) และเลือกแท็กความสนใจได้โดยไม่จำเป็นต้อง Login
- **AC-02:** ผลลัพธ์การค้นหาต้องแสดงเฉพาะข้อมูลชมรมที่เปิดเผยได้ ตรงตามเงื่อนไขที่เลือก และแสดงตัวกรองที่กำลังใช้งานอยู่
- **AC-03:** หากค้นหาแล้วไม่มีรายการตรงตามเงื่อนไข ระบบต้องแสดงข้อความแจ้งว่าไม่พบข้อมูล และผู้ใช้ยังคงเปลี่ยนหรือล้างตัวกรองได้
- **AC-04:** เมื่อกดล้างตัวกรอง ระบบต้องรีเซ็ตกลับมาแสดงรายการชมรมทั้งหมดตามค่าเริ่มต้นของหน้าค้นหา
- **AC-05:** ผู้ใช้สามารถคลิกเลือกชมรมจากรายการเพื่อเปิดดูหน้ารายละเอียดชมรมได้

## 5. Scope

### อยู่ในขอบเขต

1. แสดงรายการชมรมที่อนุญาตให้เผยแพร่
2. ค้นหาด้วยชื่อชมรม
3. กรองตามหมวดหมู่ที่ระบุใน AC-01
4. เลือกแท็กความสนใจเพื่อกรองรายการ
5. แสดงเงื่อนไขและตัวกรองที่กำลังใช้งาน
6. เปลี่ยนและล้างตัวกรอง
7. แสดงสถานะกำลังโหลด ไม่พบข้อมูล และโหลดข้อมูลไม่สำเร็จ
8. เชื่อมรายการไปยังหน้ารายละเอียดชมรมของ US-02

### ไม่รวมใน Story นี้

- การแสดงรายละเอียดชมรมเต็มหน้า ซึ่งอยู่ใน US-02
- การสมัครเข้าชมรมหรือการจัดการใบสมัคร
- การเพิ่ม แก้ไข หรือลบข้อมูลชมรม หมวดหมู่ และแท็ก
- ระบบแนะนำชมรมเฉพาะบุคคล คะแนนความเหมาะสม หรือ AI Matching
- การเพิ่มตัวกรองอื่น เช่น คณะ วิทยาเขต หรือสถานะเปิดรับสมัคร โดยไม่มีการปรับ Scope
- การบันทึกประวัติการค้นหาหรือรายการโปรด

## 6. Business Rules

| รหัส | กฎ | อ้างอิง |
|---|---|---|
| BR-01 | หน้ารายการและ API สาธารณะที่ใช้ค้นหาต้องไม่บังคับ Login | AC-01 |
| BR-02 | แสดงเฉพาะชมรมที่อนุญาตให้เผยแพร่ตามเกณฑ์ของระบบ ไม่กรองข้อมูลลับเฉพาะบน Frontend | AC-02 |
| BR-03 | การค้นหาด้วยชื่อ หมวดหมู่ และแท็กต้องใช้ข้อมูลจริงของชมรม ผลลัพธ์ต้องตรงกับกติกาการจับคู่ที่ทีมยืนยัน | AC-01, AC-02 |
| BR-04 | ตัวกรองที่แสดงบนหน้าจอต้องตรงกับเงื่อนไขที่ใช้ดึงผลลัพธ์ ไม่มีตัวกรองซ่อนอยู่โดยผู้ใช้ไม่ทราบ | AC-02 |
| BR-05 | เมื่อไม่มีผลลัพธ์ ให้แสดงข้อความ “ไม่พบชมรมที่ตรงกับเงื่อนไขการค้นหา” และยังใช้ตัวกรอง/ปุ่มล้างได้ | AC-03 |
| BR-06 | การล้างต้องกลับไปยังชุดข้อมูลสาธารณะและค่าเริ่มต้นของหน้าค้นหา ไม่เปิดเผยชมรมที่ซ่อนอยู่ | AC-04 |
| BR-07 | การเลือกชมรมต้องเปิดหน้ารายละเอียดของชมรมที่เลือก โดยอ้างอิงตัวระบุชมรมที่ถูกต้อง | AC-05 |
| BR-08 | หนึ่งชมรมต้องไม่แสดงซ้ำเพียงเพราะมีหลายแท็กที่ตรงเงื่อนไข | AC-02 |
| BR-09 | การโหลดข้อมูลล้มเหลวต้องไม่แสดงเหมือนเป็นผลค้นหาว่าง ให้แจ้งข้อผิดพลาดและเปิดทางให้ลองใหม่ | Quality Criteria |

“รายการชมรมทั้งหมด” ใน AC-04 หมายถึงชมรมทั้งหมดที่เปิดเผยได้ภายใต้ค่าเริ่มต้น ไม่ได้หมายถึงข้อมูลทุกแถวในฐานข้อมูล หากใช้ Pagination ยังสามารถแบ่งการแสดงผลเป็นหน้าได้

ชมรมที่ไม่มีรอบรับสมัครเปิดอยู่ยังค้นพบได้หากชมรมนั้นเปิดเผยได้ Story นี้ไม่ได้กำหนดให้แสดงเฉพาะชมรมที่กำลังรับสมัคร

## 7. Main Flow และ Alternative Flows

### Main Flow

1. ผู้ใช้เปิดหน้าค้นหาชมรมโดยไม่ต้อง Login
2. ระบบแสดงรายการชมรมสาธารณะตามค่าเริ่มต้น พร้อมช่องค้นหา หมวดหมู่ และแท็ก
3. ผู้ใช้ระบุชื่อชมรมหรือเลือกเงื่อนไขกรอง
4. ระบบค้นหาตามเงื่อนไขและแสดงรายการ พร้อมตัวกรองที่ใช้อยู่
5. ผู้ใช้ปรับเงื่อนไขหรือล้างตัวกรองได้
6. ผู้ใช้เลือกชมรมจากรายการ
7. ระบบเปิดหน้ารายละเอียดชมรมนั้นตาม US-02

### Alternative Flows

| กรณี | พฤติกรรมที่คาดหวัง |
|---|---|
| ไม่มีรายการตรงเงื่อนไข | แจ้งไม่พบข้อมูล โดยเก็บเงื่อนไขไว้ให้ผู้ใช้แก้ไขหรือล้าง |
| กดล้างตัวกรอง | กลับค่าเริ่มต้นและโหลดรายการชมรมสาธารณะตามค่าเริ่มต้น |
| โหลดข้อมูลไม่สำเร็จ | แสดงข้อความข้อผิดพลาด และให้ลองใหม่โดยไม่อ้างว่าไม่มีชมรม |
| เปลี่ยนเงื่อนไขระหว่างโหลด | เมื่อโหลดเสร็จ ผลที่แสดงต้องตรงเงื่อนไขล่าสุด ไม่ถูกผลเก่าทับ |
| ชมรมถูกซ่อน/ลบหลังรายการโหลดแล้ว | หน้ารายละเอียดจัดการกรณีไม่พบตาม US-02 ไม่เปิดเผยข้อมูลที่ถูกซ่อน |

## 8. ข้อมูลที่เกี่ยวข้อง

| Domain Object | ข้อมูลที่ใช้ใน Story |
|---|---|
| Club | ตัวระบุ ชื่อ ข้อมูลสรุปสำหรับรายการ และเงื่อนไขการเปิดเผย |
| Club Category | ตัวระบุและชื่อหมวดหมู่ของชมรม |
| Interest Tag | ตัวระบุและชื่อแท็กความสนใจ |
| ความสัมพันธ์ Club–Tag | ใช้ค้นหาชมรมตามแท็กโดยไม่สร้างรายการซ้ำ |

รายการฟิลด์ที่แสดงบนการ์ดชมรม เช่น คำอธิบายย่อหรือรูปภาพ ให้ยืนยันใน UI/API Design โดยไม่ส่งข้อมูลภายในที่ไม่จำเป็น การกำหนดชื่อฟิลด์ Endpoint และตารางจริงอยู่ในขั้น Design

## 9. Quality Criteria และ Constraints

| ประเด็น | เกณฑ์ |
|---|---|
| ความถูกต้อง | ผลลัพธ์ตรงเงื่อนไขที่ใช้อยู่ ไม่แสดงชมรมซ้ำจากความสัมพันธ์หลายแท็ก |
| การเปิดเผยข้อมูล | Public API ส่งเฉพาะข้อมูลที่อนุญาต ไม่ส่งข้อมูลใบสมัคร สมาชิก ข้อมูลบัญชี หรือรอบ Draft |
| การใช้งาน | ช่องค้นหา ตัวกรอง และปุ่มล้างมีชื่อชัดเจน ใช้งานได้บนหน้าจอมือถือและ Desktop |
| สถานะหน้าจอ | Loading, Empty และ Error แยกกันอย่างชัดเจน |
| ความสอดคล้อง | ใช้เกณฑ์ชมรมสาธารณะเดียวกับ US-02 และใช้ Contract เดียวกันทั้ง Frontend/Backend |
| ประสิทธิภาพ | ไม่กำหนดเวลา Response หรือตัวเลขจำนวนผลลัพธ์ขึ้นใหม่ใน Story นี้ ใช้ NFR กลางที่ทีมตกลง |
| การตรวจสิทธิ์ | เปิดสาธารณะเฉพาะ Method/Endpoint ที่จำเป็น ไม่เปิดทุก API ใต้ Path ชมรมแบบกว้าง |
| ขอบเขตข้อมูล | ใช้หมวดหมู่/แท็กที่มีในระบบ ผู้ใช้หน้านี้ไม่มีสิทธิ์สร้างหรือแก้ Master Data |

## 10. ประเด็นที่ต้องยืนยันก่อนพัฒนา

AC ปัจจุบันยังไม่ระบุรายละเอียดต่อไปนี้ ตารางนี้เป็นข้อเสนอเพื่อให้ทีมตัดสินใจ ไม่ใช่ข้อกำหนดที่อนุมัติแล้ว

| ประเด็น | ข้อเสนอแบบเรียบง่ายสำหรับ MVP |
|---|---|
| วิธีจับคู่ชื่อ | ค้นหาแบบมีคำค้นเป็นส่วนหนึ่งของชื่อ ตัดช่องว่างหัวท้าย และไม่แยกตัวพิมพ์เล็ก/ใหญ่ภาษาอังกฤษ |
| คำค้นว่างหรือมีแต่ช่องว่าง | ถือว่าไม่กรองด้วยชื่อ โดยยังใช้ตัวกรองอื่นที่เลือก |
| ชื่อ + หมวดหมู่ + แท็ก | ใช้ AND ระหว่างกลุ่มเงื่อนไข เพื่อให้ผลตรงทุกกลุ่มที่เลือก |
| จำนวนหมวดหมู่ที่เลือก | เลือกครั้งละหนึ่งหมวดหมู่ หรือเลือก “ทั้งหมด” |
| จำนวนแท็กที่เลือก | เริ่มจากหนึ่งแท็กเพื่อลดความซับซ้อน หากต้องเลือกหลายแท็กต้องกำหนด ANY/ALL ให้ชัดก่อนพัฒนา |
| ขอบเขตปุ่มล้าง | ล้างคำค้น หมวดหมู่ และแท็กทั้งหมด แล้วกลับไปหน้าแรกหากมี Pagination |
| ค่าเริ่มต้น | กำหนดลำดับเรียงที่แน่นอน และขนาดหน้าหากใช้ Pagination ในขั้น Design |
| Trigger การค้นหา | เลือกปุ่มค้นหา/Enter หรือค้นหาระหว่างพิมพ์อย่างใดอย่างหนึ่งให้ UI และ Tests ใช้ตรงกัน |
| สถานะชมรมสาธารณะ | อ้างอิงเกณฑ์จริงของ US-02/Schema ไม่สมมติว่า ACTIVE เท่ากับเผยแพร่ได้เสมอ |

เมื่อยืนยันแล้ว ให้นำข้อสรุปไปใส่ใน Business Rules/API Contract และเติม Expected Results ของกรณีทดสอบที่เกี่ยวข้อง

## 12. Definition of Done

- [ ] ทีมยืนยันรายละเอียดการค้นหา/กรองในหัวข้อ 10 ที่จำเป็นต่อการพัฒนาแล้ว
- [ ] AC-01 ถึง AC-05 ผ่าน พร้อมหลักฐานทดสอบ
- [ ] Backend กรองข้อมูลที่เปิดเผยได้จริง และทดสอบเรียก Public API โดยตรง
- [ ] Frontend แสดงตัวกรองและผลลัพธ์ตรงกัน รวม Loading/Empty/Error
- [ ] เปลี่ยน/ล้างตัวกรองและเปิดรายละเอียด US-02 ได้
- [ ] Automated Tests ของกฎค้นหา/กรองและพฤติกรรม UI สำคัญผ่าน
- [ ] Build, Type Check และ Tests ที่เกี่ยวข้องผ่าน CI
- [ ] ผ่าน Code Review แก้ข้อเสนอแนะที่ขัดเกณฑ์ตรวจรับ และรวมโค้ดตามกติกาทีมแล้ว
- [ ] ทดสอบร่วม Frontend/Backend บน Environment ทดสอบที่ระบุ พร้อมบันทึกผลใน Test Report
- [ ] ไม่มีข้อผิดพลาดคงค้างที่ทำให้ค้นหาไม่ได้ ผลลัพธ์ผิด หรือเปิดเผยข้อมูลที่ไม่อนุญาต
