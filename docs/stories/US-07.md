# US-07: จัดการรอบรับสมัคร

## Description

**As a:** กรรมการชมรมที่มีสิทธิ์จัดการรอบรับสมัคร  
**I want to:** สร้าง แก้ไข เผยแพร่ และปิดรอบรับสมัคร กำหนดวันเปิด–ปิด คุณสมบัติ และกำหนดประกาศผล  
**So that:** ฉันสามารถจัดการการรับสมัครตามแผน และแจ้งกำหนดการแก่นักศึกษาชัดเจน

**Sprint:** Sprint 1  
**Priority:** High | **Estimate:** 3 Story Points

**Pre-conditions:** Login สำเร็จและมีสิทธิ์กรรมการของชมรมเป้าหมาย  
**Post-conditions:** รอบที่เผยแพร่ปรากฏบน Open Call Board และรับใบสมัครตามกำหนด หากปิดรอบแล้วจะไม่รับใบสมัครใหม่

## Acceptance Criteria

- **AC-01:** กรรมการชมรมสามารถสร้าง แก้ไข เผยแพร่ และปิดรอบรับสมัคร กำหนดวันเวลาเปิด–ปิด คุณสมบัติ และกำหนดประกาศผลได้
- **AC-02:** เวลาเปิดรับสมัครต้องมาก่อนเวลาปิดรับสมัครเสมอ หากไม่ถูกต้องระบบต้องปฏิเสธ
- **AC-03:** รอบที่เผยแพร่แล้วและถึงเวลาเปิดรับ โดยยังไม่ถึงเวลาปิดและไม่ถูกปิดก่อนกำหนด ต้องปรากฏบน Open Call Board ในสถานะ **“เปิดรับสมัคร”**
- **AC-04:** กรรมการสั่งปิดรับสมัครก่อนกำหนดได้ ระบบหยุดรับใบสมัครใหม่ทันทีและบันทึกเวลาปิดจริง
- **AC-05:** ผู้ที่ Login แล้วแต่ไม่มีสิทธิ์กรรมการของชมรมเป้าหมาย ไม่สามารถสร้าง แก้ไข หรือปิดรอบได้ โดย Backend ตอบ **403 Forbidden** การเผยแพร่ต้องตรวจสิทธิ์เดียวกัน

## ข้อมูลหลัก

| Field | ความหมาย |
|---|---|
| `title`, `description` | ชื่อรอบและรายละเอียดประกาศ |
| `eligibility_text` | ข้อความคุณสมบัติผู้สมัคร |
| `opens_at`, `closes_at` | วันเวลาเปิดและปิดรับสมัครตามกำหนด |
| `results_scheduled_at` | กำหนดวันเวลาประกาศผล |
| `publication_status`, `published_at` | สถานะการเผยแพร่และเวลาที่เผยแพร่ |
| `closed_at` | เวลาปิดก่อนกำหนด; เป็น `null` หากไม่ได้สั่งปิดก่อนกำหนด |

ตารางนี้แสดงเฉพาะข้อมูลหลักของ Story ไม่ใช่ Schema ทั้งหมด ส่วน `eligibility_text` เป็นข้อความแจ้งคุณสมบัติ ไม่ใช่เงื่อนไขที่ระบบแปลงเป็นกฎตรวจผู้สมัครอัตโนมัติ

## Business Rules

| รหัส | กฎ | อ้างอิง |
|---|---|---|
| BR-01 | ตรวจสิทธิ์กรรมการของชมรมเป้าหมายที่ Backend ทุกครั้งที่สร้าง แก้ไข เผยแพร่ หรือปิดรอบ | AC-01, AC-05 |
| BR-02 | รอบใหม่เป็น Draft กรรมการบันทึกและแก้ข้อมูลรอบ รวมคุณสมบัติและกำหนดประกาศผลได้ ข้อมูลที่แก้ต้องผ่าน Validation ก่อนบันทึก | AC-01 |
| BR-03 | `opens_at < closes_at` เสมอ ทั้งตอนสร้างและแก้ไข เวลาเท่ากันหรือสลับกันให้ปฏิเสธ | AC-02 |
| BR-04 | เมื่อเผยแพร่ ให้บันทึกสถานะ Published และ `published_at` แล้วแสดงรอบบน Open Call Board โดย Draft ต้องไม่ปรากฏต่อผู้สมัคร | AC-01, AC-03 |
| BR-05 | เปิดรับเมื่อรอบ Published และ `opens_at <= เวลาปัจจุบัน < closes_at` และ `closed_at` เป็น `null` ก่อนเวลาเริ่มให้แสดง “ยังไม่เปิดรับ” | AC-03 |
| BR-06 | เมื่อถึง `closes_at` ให้แสดง “ปิดรับสมัคร” และปฏิเสธใบสมัครใหม่ โดยใช้เวลา Server ตรวจ ไม่ต้องรอการเปิดหน้าเว็บ | AC-02, AC-03 |
| BR-07 | เมื่อสั่งปิดก่อนกำหนดสำเร็จ ให้บันทึก `closed_at` จากเวลา Server คง `closes_at` เดิม และหยุดรับใบสมัครใหม่ทันที การปิดไม่ลบหรือยกเลิกใบสมัครเดิม | AC-04 |
| BR-08 | การกำหนดหรือแก้ `results_scheduled_at` เป็นการแจ้งกำหนดการ ไม่ใช่การเผยแพร่ผลคัดเลือกจริง | AC-01 |

**สถานะ:** Draft = ยังไม่เผยแพร่; Published = เผยแพร่แล้ว โดยเปิดรับตามช่วงเวลา; Closed = ปิดก่อนกำหนดหรือถึงเวลาสิ้นสุดแล้ว

**ให้ตรงกับ ERD:** Closed เป็นสถานะคำนวณ ไม่ต้องเพิ่ม `CLOSED` ใน `publication_status` เมื่อปิดตามกำหนด `closed_at` คงเป็น `null` และใช้ `closes_at` เป็นเวลาสิ้นสุด ส่วนการสั่งปิดซ้ำต้องไม่เขียนทับเวลาปิดครั้งแรก

| กรรมการแก้ข้อมูลรอบ รวมคุณสมบัติและกำหนดประกาศผล โดยข้อมูลถูกต้อง | บันทึกและแสดงค่าที่แก้ไข | AC-01 |
| สร้างหรือแก้ไขโดยเวลาเริ่มเท่ากับ/หลังเวลาสิ้นสุด | ปฏิเสธและไม่บันทึกข้อมูลที่ผิด | AC-02 |
| นักศึกษาเปิด Open Call Board ขณะรอบยังเป็น Draft | ไม่เห็นรอบดังกล่าว | AC-03 |
| เผยแพร่ก่อนเวลาเปิดรับ | เห็นรอบบน Board แต่ยังสมัครไม่ได้ | AC-01, AC-03 |
| ถึงเวลาเปิดรับพอดีและรอบยังไม่ปิด | Board แสดง “เปิดรับสมัคร” และสมัครได้ | AC-03 |
| ถึงเวลาปิดรับพอดี | แสดง “ปิดรับสมัคร” และรับใบสมัครใหม่ไม่ได้ | AC-03 |
| กรรมการปิดรอบระหว่างเปิดรับ | หยุดรับทันที เก็บ `closed_at` คง `closes_at` และใบสมัครเดิม | AC-04 |
| ผู้สมัครเปิดฟอร์มไว้แล้วส่งหลังรอบถูกปิด | Backend ปฏิเสธและไม่สร้างใบสมัคร | AC-04 |
| ผู้ที่ Login แล้วแต่ไม่มีสิทธิ์ชมรมเป้าหมายเรียก API สร้าง/แก้ไข/เผยแพร่/ปิด | ทุกคำขอถูกปฏิเสธด้วย 403 และข้อมูลไม่เปลี่ยน | AC-05 |

## ขอบเขตและเรื่องที่ยังต้องตกลง

- **อยู่ใน Story:** จัดการรอบ เวลา คุณสมบัติ กำหนดประกาศผล และการแสดงรอบบน Open Call Board
- **แยกไป Story อื่น:** จัดการคำถามคัดเลือก (US-08) และบันทึก/เผยแพร่ผลคัดเลือกจริง
- **ยังไม่ถือเป็นเกณฑ์ตรวจรับ:** การเปิดรอบกลับ การแก้เวลาหลังมีใบสมัคร การสั่งปิดก่อนถึงเวลาเริ่ม และความสัมพันธ์ของกำหนดประกาศผลกับเวลาปิดรับ ต้องตกลงก่อนนำมาเป็นข้อจำกัดเพิ่มเติม
- **จุดที่ต้องตรวจร่วมกับ ERD:** ปัจจุบันเงื่อนไข `closed_at >= opens_at` รองรับการสั่งปิดหลังเริ่มรับแล้ว หากตกลงให้ปิดก่อนเริ่มได้ ต้องปรับเงื่อนไขฐานข้อมูลให้ตรงกัน
