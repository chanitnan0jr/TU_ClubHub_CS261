# US-08: จัดการคำถามคัดเลือกของรอบรับสมัคร

**สถานะ 19 ต.ค. 2026:** Backend รับชุด `questions` ผ่าน POST/PUT ของรอบตาม [Recruitment Contract](../api/rounds.openapi.yaml) แล้ว ไม่มี API แยกรายคำถาม หน้า QuestionManagementPage ยังใช้ข้อมูลตัวอย่างและ client ที่เรียก path คนละชุดกับ Contract จึงยังต้องเชื่อมและปรับให้ตรงกัน

## Description

**As a:** กรรมการชมรมที่มีสิทธิ์จัดการคำถามของรอบรับสมัคร  
**I want to:** เพิ่ม แก้ไข ลบ และเรียงลำดับคำถามคัดเลือกแบบข้อความ รวมถึงกำหนดข้อบังคับตอบ  
**So that:** ฉันสามารถออกแบบคำถามให้ตรงกับข้อมูลที่ชมรมต้องการใช้พิจารณา

**Sprint:** Sprint 1  
**Priority:** High | **Estimate:** 2 Story Points

**Pre-conditions:** มีรอบรับสมัครของชมรมตนเองอยู่ในระบบ และอยู่ในสถานะที่อนุญาตให้แก้ไข  
**Post-conditions:** แบบฟอร์มสมัครแสดงคำถามตามที่บันทึกถูกต้อง

## Acceptance Criteria

- **AC-01:** กรรมการชมรมสามารถเพิ่ม แก้ไข ลบ และจัดเรียงลำดับคำถามคัดเลือกแบบข้อความในรอบรับสมัครของตนเองได้
- **AC-02:** สามารถกำหนดสถานะบังคับตอบ (Required) สำหรับคำถามแต่ละข้อได้ และไม่อนุญาตให้บันทึกข้อความคำถามที่ว่างเปล่า
- **AC-03:** ในแบบฟอร์มการสมัคร คำถามต้องแสดงตามลำดับที่กรรมการจัดเรียงไว้ถูกต้อง
- **AC-04:** ระบบต้องป้องกันการลบคำถามที่มีคำตอบจากผู้สมัครอ้างอิงอยู่ เพื่อไม่ให้ข้อมูลใบสมัครเดิมเสียหาย
- **AC-05:** การแก้ไขคำถามของรอบหนึ่งต้องไม่มีผลกระทบต่อชุดคำถามของรอบอื่นหรือชมรมอื่น

**นโยบายเพิ่มเติมตามโจทย์:** ห้ามแก้ไขคำถามที่มีผู้สมัครตอบแล้วด้วย แม้ AC-04 จะกล่าวถึงเฉพาะการลบ

## ข้อมูลหลัก

| Field | ความหมาย |
|---|---|
| `id`, `round_id` | รหัสคำถามและรอบรับสมัครที่คำถามสังกัด |
| `prompt` | ข้อความคำถาม |
| `display_order` | ลำดับแสดงผล เป็นจำนวนเต็มบวก |
| `is_required` | คำถามบังคับตอบหรือไม่ |

## Business Rules

| รหัส | กฎ | อ้างอิง |
|---|---|---|
| BR-01 | Backend ตรวจสิทธิ์กรรมการของชมรมเป้าหมายและสถานะรอบที่อนุญาตให้แก้ไขทุกครั้ง | AC-01, Pre-conditions |
| BR-02 | รองรับเฉพาะคำถามที่รับคำตอบเป็นข้อความ ข้อความคำถามต้องไม่ว่างหรือมีแต่ช่องว่าง | AC-01, AC-02 |
| BR-03 | แต่ละคำถามกำหนด Required ได้ หากบังคับตอบ ผู้สมัครต้องกรอกข้อความที่ไม่ว่างหรือมีแต่ช่องว่างก่อนส่งใบสมัคร หากไม่บังคับสามารถเว้นคำตอบได้ | AC-02 |
| BR-04 | แสดงคำถามตาม `display_order` จากน้อยไปมาก ลำดับต้องมากกว่า 0 และไม่ซ้ำภายในรอบเดียวกัน การเรียงใหม่ต้องคง ID ของคำถามเดิม | AC-01, AC-03 |
| BR-05 | หากมีรายการคำตอบอ้างอิงคำถาม ห้ามลบหรือแก้ไขคำถามนั้น รวมข้อความ Required และลำดับแสดงผล โดยรักษาคำตอบเดิมทั้งหมด | AC-04 และนโยบายตามโจทย์ |
| BR-06 | ทุกคำถามต้องเป็นของรอบที่กำลังจัดการ ห้ามใช้ ID ของคำถามต่างรอบเพื่อแก้ไข ลบ หรือจัดลำดับ และห้ามเปลี่ยนรอบสังกัดของคำถามผ่านการแก้ไข | AC-05 |
| BR-07 | การบันทึกชุดลำดับต้องสำเร็จครบหรือไม่เปลี่ยนข้อมูลเลย และต้องไม่เปลี่ยนลำดับของคำถามที่ถูกล็อกตาม BR-05 | AC-03, AC-04 |

**หลักการล็อก:** ตรวจเป็นรายคำถาม ไม่ถือว่าการมีใบสมัครหนึ่งใบทำให้ทั้งชุดคำถามถูกล็อกโดยอัตโนมัติ คำถามที่ไม่มีคำตอบยังจัดการได้เมื่อผ่านสิทธิ์และนโยบายสถานะรอบ

**ลำดับไม่จำเป็นต้องติดกัน:** เช่น 1, 3, 5 ยังแสดงผลได้ถูกต้อง ไม่ต้องเปลี่ยนเลขของคำถามที่มีคำตอบแล้วเพียงเพื่อให้ลำดับต่อเนื่อง

**รักษาข้อมูลเดิม:** Backend ต้องตรวจคำตอบอ้างอิงขณะบันทึกและป้องกันการแก้/ลบชนกับการส่งคำตอบใหม่ ห้ามลบคำตอบตามไปด้วยเพื่อให้ลบคำถามได้

## ขอบเขตและเรื่องที่ยังต้องตกลง

- **อยู่ใน Story:** คำถามแบบข้อความ การเพิ่ม/แก้ไข/ลบ/จัดลำดับ Required และการรักษาคำถามที่มีคำตอบแล้ว
- **การทำงานร่วมกับ US-03:** US-08 กำหนดคำถามและ Required; API ส่งใบสมัครของ US-03 ต้องตรวจ Required ซ้ำที่ Backend
- **ยังต้องตกลง:** สถานะรอบใดอนุญาตให้แก้ไข และการเพิ่มคำถามบังคับใหม่หลังมีใบสมัครแล้ว โดยไม่ย้อนบังคับให้ใบสมัครที่ส่งสำเร็จต้องตอบเพิ่ม
- **ไม่เพิ่มเป็นข้อกำหนด:** การล็อกทั้งชุดหลังใบสมัครแรก คำถามแบบตัวเลือก ไฟล์อัปโหลด หรือระบบหลายเวอร์ชันของแบบฟอร์ม
